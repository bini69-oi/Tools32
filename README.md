<h1 align="center">Tools32</h1>

<p align="center">Установка и обслуживание <a href="https://docs.rw">Remnawave</a> — панель, ноды, реверс-прокси.<br>
Бесплатно, MIT, без телеметрии.</p>

---

> [!WARNING]
> Версия 0.1.0 — заложен фундамент: предполётные проверки, откат при падении,
> единый реестр версий, тесты и CI. Установщик панели и ноды — в работе,
> следующий релиз. Пока скрипт умеет проверять сервер и показывать, что будет
> поставлено.

## Зачем ещё один скрипт

Есть [remnawave-reverse-proxy](https://github.com/eGamesAPI/remnawave-reverse-proxy) — рабочий и живой проект, из
которого Tools32 вырос и чью MIT-лицензию сохраняет. Отличия не в фичах, а в том,
как скрипт ведёт себя, когда что-то идёт не так.

| | remnawave-reverse-proxy | Tools32 |
|---|---|---|
| Строгий режим bash | нет ни в одном файле | `set -euo pipefail` + трассировка падения |
| Падение на середине | сервер остаётся в полусостоянии | журнал отката разбирает созданное |
| Проверки до установки | root, место перед апгрейдом | ОС, память, диск, порты, DNS, часы, старая установка — одним списком |
| Версии образов | прописаны в 6 похожих шаблонах | один реестр `lib/versions.sh` |
| Тесты | нет | юнит-тесты без зависимостей + CI на 4 дистрибутивах |
| Сторож пинов | нет | CI проверяет, что теги живы и не вышло новее |
| Пароль Postgres | `postgres` у всех | генерируется под установку |
| Секрет подписи вебхуков | одна строка на всех, лежит в репозитории | генерируется под установку |

Конкретный пример, чего стоит дублирование: фикс «страница подписки 8.0.0 под
панель 3.x» в апстриме попал в один из четырёх compose-шаблонов, остальные три
продолжили тянуть `subscription-page:latest` рядом с `backend:3`. В Tools32 пара
«панель ↔ страница подписки» объявлена один раз и покрыта тестом.

## Установка

```bash
bash <(curl -Ls https://raw.githubusercontent.com/bini69-oi/Tools32/main/install.sh) check
```

Или из клона:

```bash
git clone https://github.com/bini69-oi/Tools32.git && cd Tools32 && bash install.sh help
```

## Команды

| Команда | Что делает |
|---|---|
| `install.sh check [роль] [домен...]` | проверяет сервер: ОС, память, диск, порты, DNS, часы |
| `install.sh versions` | показывает, какие образы будут поставлены |
| `install.sh render <роль> <прокси>` | печатает docker-compose.yml |
| `install.sh version` | версия скрипта |

Роли: `panel`, `node`, `panel-node`.

```bash
bash install.sh check panel panel.example.com sub.example.com
bash install.sh check node node.example.com
```

## Требования

Debian 12+ или Ubuntu 22.04+, root, x86_64 или arm64. Под панель — 2 ГБ памяти и
20 ГБ диска, под ноду — 1 ГБ и 10 ГБ. Свой домен обязателен.

## Что ставится

| Компонент | Версия |
|---|---|
| Remnawave Panel | 3.4.3 |
| Remnawave Node | 3.4.1 |
| Subscription page | 8.0.0 |
| PostgreSQL | 18.6 |
| Valkey | 9.1.2-alpine |
| Caddy | 2.11.4 |

Точные пины, не `latest`: обновление образа под работающей панелью не должно
случаться само по себе. CI ежедневно проверяет, что теги живы и не вышло новее.

## Разработка

```bash
bash tests/run.sh                        # юнит-тесты, зависимостей нет
shellcheck -x $(git ls-files '*.sh')     # статический анализ
bash tools/check-images.sh               # живы ли пины образов
```

Структура:

```
install.sh          точка входа
lib/boot.sh         строгий режим, загрузчик модулей, ловушка ошибок
lib/log.sh          логи на экран и в файл
lib/journal.sh      журнал отката
lib/preflight.sh    предполётные проверки
lib/versions.sh     единый реестр версий образов
lib/compose.sh      генератор docker-compose.yml на все роли и прокси
lib/secrets.sh      пароли, логины, ключи
lib/env.sh          генерация .env для панели и ноды
tools/              служебные скрипты для CI
tests/              тесты и раннер
```
